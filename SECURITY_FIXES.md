# Security fixes

- **Account and admin authorization** in `src/lib/auth.ts`, `src/lib/auth-guard.ts`, `src/app/api/auth/me/route.ts`, `src/lib/wallet-db.ts` and navigation consumers. Removed email promotion, required verified Google identity and failed closed for absent canonical accounts. Profile lookup requires a session. Existing ADMIN database rows retain authority.
- **MFA and invoices** in `src/app/api/products/route.ts`, `src/app/api/orders/[id]/invoice/route.ts` and `src/lib/invoicing/tokens.ts`. Admin catalog writes require MFA, account invoices check canonical user ID, and HMAC generation requires the configured signing secret.
- **Credential removal and TLS** in the five database/mail diagnostic scripts, `src/lib/email-service.ts`, `src/lib/email-marketing/provider.ts` and the historical findings document. Diagnostics read server configuration, sanitize errors and require an explicit recipient for test delivery.
- **Automation** in `scripts/check-secrets.mjs`, `scripts/test-auth-boundaries.mjs`, `.github/workflows/security.yml` and `.githooks/pre-commit`. The gate flags known secret patterns and private files. Run `node scripts/check-secrets.mjs --staged` before committing or enable the optional hook with `git config core.hooksPath .githooks`.
- **Verification**. TypeScript, local env validation, dependency audit and isolated auth boundary tests passed. Tests cover unauthenticated profile lookup, nonadmin denial, stale-role revocation and MFA lookup failure. An isolated production build passed with synthetic credentials and no reachable database. A browser asset scan found no exact local credential matches.
