## 1. Executive Summary

The Customer Analytics and Segmentation module delivers commercial intelligence directly into the administrative control center. By calculating customer unit economics (LTV, AOV, order frequency) and applying dynamic segmentation tags, the platform enables targeted promotions, VIP white-glove support, and proactive churn intervention.

## 2. Quantitative Commercial Metrics

Within `/admin/users/[id]`, financial metrics are aggregated in real-time from the transactional database:

### 2.1 Formulae & Definitions

| Metric | Formula | Description & Business Usage |
| :--- | :--- | :--- |
| **Lifetime Value (LTV)** | $\text{LTV} = \sum \text{Completed Orders Amount (BDT)}$ | Total cumulative gross revenue generated by this customer. |
| **Average Order Value (AOV)** | $\text{AOV} = \frac{\text{LTV}}{\text{Total Completed Orders}}$ | Average spend per transaction; informs upselling potential. |
| **Wallet Utilization Ratio** | $\text{Ratio} = \frac{\sum \text{Wallet Purchases}}{\sum \text{Wallet Deposits}}$ | High ratio indicates active store currency usage; low ratio indicates idle balances. |
| **Order Frequency** | $\text{Velocity} = \frac{\text{Completed Orders}}{\text{Days Since Registration}}$ | Rate of repeat purchases over time. |
| **Support Cost Index** | $\text{Tickets per Order} = \frac{\text{Total Support Tickets}}{\text{Total Orders}}$ | Ratio identifying customers requiring high operational support overhead. |

## 3. Dynamic Customer Tagging Engine (`user_tags`)

Customers can be tagged manually by staff or automatically by system automation rules.

```sql
CREATE TABLE `user_tags` (
  `id` VARCHAR(191) NOT NULL PRIMARY KEY,
  `userId` VARCHAR(191) NOT NULL,
  `tag` VARCHAR(50) NOT NULL,
  `color` VARCHAR(20) NOT NULL DEFAULT 'slate',
  `assignedBy` VARCHAR(100) NOT NULL DEFAULT 'admin',
  `createdAt` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE INDEX `uniq_user_tag` (`userId`, `tag`),
  INDEX `idx_user_tags_userId` (`userId`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.1 Standard Tag Catalog

| Tag Name | Color | Assignment | Criteria / Description |
| :--- | :--- | :--- | :--- |
| **`VIP Customer`** | `amber` | Automated / Manual | Cumulative spend $\ge 25,000\text{ BDT}$ or manually designated key account. |
| **`Wholesale Reseller`**| `blue` | Manual | Approved B2B reseller purchasing digital stock in bulk. |
| **`New Customer`** | `emerald`| Automated | Account age $< 30\text{ days}$ with at least 1 completed purchase. |
| **`At-Risk / Inactive`** | `orange` | Automated | Previously active customer with zero orders in the last 90 days. |
| **`Fraud Watchlist`** | `rose` | Automated / Manual | Flagged for suspicious login attempts or unusual payment behavior. |
| **`Corporate Account`** | `purple` | Manual | Verified corporate customer with dedicated invoicing requirements. |

## 4. Automated VIP Promotion (`RULE_HIGH_VALUE_VIP_TAG`)

The automation rules service includes an automated rule that continuously evaluates customer spend:
- **Condition:** When an order transitions to `COMPLETED`, if the customer's cumulative completed spend exceeds `25,000 BDT` and the tag `VIP Customer` is not yet present.
- **Action:**
  1. Inserts `VIP Customer` tag with color `amber` into `user_tags`.
  2. Dispatches a celebratory notification to the customer thanking them for their loyalty.
  3. Escalates the customer's support routing priority to `HIGH`.
  4. Records the automated event in `AdminAuditLog`.

## 5. Segmented Admin User Listing

On the main user listing page (`/admin/users`), administrators can filter the user base using quick segment presets:
- **All Customers**
- **VIP Accounts** (`?segment=vip`)
- **Resellers** (`?role=RESELLER`)
- **Restricted Users** (`?status=SUSPENDED,BANNED`)
- **At-Risk Inactive** (`?segment=inactive`)

This enables bulk communication, promotional gift drops, and targeted account maintenance across defined customer cohorts.
